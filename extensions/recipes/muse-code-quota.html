Muse Code Quota Widget Recipe

Capability

Show the Muse Code subscription tier, session-window usage, and weekly usage with official reset times, acquired only through the installed official CLI.

The sole quota source is muse usage --json, which prints one JSON envelope with tier, window, and weekly allowance fields.

Never read the ai.meta.dev.credentials keychain item directly. The official CLI owns that item and rewrites it on token refresh, which drops any "Always Allow" grant - so every direct keychain read re-prompts on nearly every widget refresh.

Never call the Muse key endpoint directly and never handle a Muse bearer token in the extension; the CLI owns credential storage, refresh, and selection.

This recipe is self-contained and requires no external implementation guide.

Recommended Data Source Order

PrioritySourceContract
1Official CLI (muse usage --json)Fresh tier, session-window, and weekly usage from the credential owner.
2Last-good snapshot cacheSame-extension stored snapshot for eligible transient failures only, rendered visibly stale.

There is no file, keychain, or direct-API fallback source. A missing CLI is an explicit unavailable outcome, not a reason to reach for the credential store.

Official CLI Invocation

Shell and credential-adjacent work belongs only in muse-code-quota/server.ts, behind window.babyMenu.capabilities.invoke.

Resolve the binary in this order without a shell: muse on PATH, then ~/.local/bin/muse.

Spawn the resolved binary with argument array ["usage", "--json"], shell: false, ignored stdin, the complete inherited environment, a 15-second timeout, and a 1 MiB stdout cap held only in memory.

When every candidate is missing (ENOENT), return an unavailable error naming the missing CLI. Do not probe the keychain or network as a substitute.

A nonzero exit may still print a JSON envelope with reason and hint fields; parse stdout regardless of exit status before classifying the failure.

Before writing parsing code, run the real muse usage --json on the target machine and confirm the exact field names below. Never guess the envelope shape. Its output carries no secrets, but print only the fields this recipe names.

Parser Guidance

Accept one JSON object shaped like this real envelope (values vary):

{
  "schemaVersion": 1,
  "allowance": {
    "tier": "Muse Code High Usage",
    "window": { "usedPercent": 23, "resetsAtMs": 1792877884000 },
    "weekly": { "usedPercent": 49, "resetsAtMs": 1792972800000 },
    "asOfMs": 1792876678649,
    "source": "mint"
  },
  "reason": null,
  "hint": null
}

Require allowance to be an object and at least one of allowance.window / allowance.weekly to carry a finite non-negative usedPercent.

Convert resetsAtMs to ISO 8601 only when it is a finite positive number; otherwise omit resetAt.

Read tier only when it is a non-empty string.

On a failing run, read reason for classification only: an auth/login/sign-in/unauthorized-shaped reason is sign-in-required, any other reason is a transient CLI failure. Never render the raw reason or hint text; map to the normalized user-visible errors below.

Timeouts, non-JSON output, and envelopes without a usable window are transient failures eligible for the stale snapshot.

Normalized Types

type MuseQuotaWindow = {
  id: "weekly" | "window";
  label: string;
  percentUsed: number;
  resetAt?: string;
  durationMins?: number;
};

type MuseQuotaSnapshot = {
  tier?: string;
  windows: MuseQuotaWindow[];
  refreshedAt: string;
  stale: boolean;
  lastError?: string;
  lastErrorAt?: string;
};

type QuotaResult =
  | { ok: true; data: MuseQuotaSnapshot }
  | { ok: false; error: string };

lastError carries the normalized failure message only on stale snapshots, with lastErrorAt marking when that refresh failed; fresh snapshots omit both.

Label the weekly window week and the session window session.

durationMins is optional and omitted when the CLI envelope does not report it.

User-visible errors are exactly Muse sign-in required, Muse CLI not found, muse usage timed out, or muse usage failed (with a normalized reason suffix only for non-auth CLI failures).

Implementation Contract

All shell, parse, and cache work belongs in muse-code-quota/server.ts behind window.babyMenu.capabilities.invoke.

Use context.db for one internal last-good snapshot row, keyed to a single stable table.

Only a successful CLI parse may write the snapshot. On an eligible transient failure, return the stored snapshot as stale without changing the stored bytes.

Auth and missing-CLI outcomes must not render or refresh the cache; they return their explicit error.

Single-flight the entire getQuota acquisition so startup, interval, and manual calls share one CLI run and one cache write.

Reuse the stored snapshot without spawning the CLI again while it is younger than 45 seconds, so repeat menu opens in a burst share one read.

On an eligible transient failure, attach the normalized failure message as lastError with the current time as lastErrorAt: the CLI reason suffix when present, else the trimmed first stderr line bounded to one short line, else the exit metadata. Never attach stdout payload.

Server action response shape is the QuotaResult union above.

Renderer and Refresh Contract

Export a RefreshableBabyMenuWidget with a five-minute viewRefreshIntervalMs and one shared refreshView function.

The host-owned refreshView call is the startup refresh path; a visible manual refresh control must call the same function, disable itself while pending, and never create overlapping work.

While refresh is pending, keep the currently rendered successful windows and show an updating indicator.

Render stale snapshots with an explicit stale marker, never as fresh data.

Render the stale lastError text next to the stale marker so a bare STALE never hides its cause.

Guard the fetch with a client-side timeout longer than the server timeout, and a failed fetch keeps the last good snapshot instead of blanking the widget; only a first-ever failure renders the unavailable state.

Show sign-in guidance (muse login) only for the Muse sign-in required outcome, and distinct copy for missing-CLI, timeout, and transient failures.

Normalized data arrives over window.babyMenu; do not add new preload methods for this widget.

Round only rendered percentages, never stored values.

Error Classification

  • All binary candidates missing is unavailable (Muse CLI not found).
  • A killed or timed-out CLI run is transient (muse usage timed out).
  • Non-JSON output or an envelope without a usable window is transient (muse usage failed).
  • An auth-shaped CLI reason is sign-in-required (Muse sign-in required).
  • Any other CLI reason is transient with a normalized suffix.

Diagnostics are allowlisted timeout, exit, missing-field, and one trimmed stderr line metadata only. Raw CLI output never leaves the server action.

Security Constraints

  • Acquire quota only through the official CLI and let that client own all credential storage and refresh.
  • Never read the ai.meta.dev.credentials keychain item, never run a keychain lookup utility, and never call the Muse key endpoint directly.
  • Never handle, log, return, cache, or commit bearer tokens, credential bundles, or raw keychain payloads.
  • Never pass a credential through process arguments or newly created environment variables.
  • Never expose raw CLI output, exit internals, or provider payloads to the renderer or diagnostics.

Acceptance Criteria

  • The server spawns only the resolved muse binary with ["usage", "--json"], no shell, a bounded timeout, and no keychain or direct-API path.
  • A healthy CLI run never touches the macOS keychain from the extension, so no system prompt appears on refresh.
  • Missing CLI, timeout, malformed output, auth-shaped, and other CLI failures map deterministically to the documented normalized errors.
  • Only successful parses write the snapshot, and only transient failures render it stale.
  • Concurrent getQuota calls share one CLI run and one cache write.
  • The finished server action is verified against the real muse usage --json output before reporting done; reasoning about the envelope on paper is not verification.
  • No bearer token, credential bundle, keychain payload, raw CLI output, or provider body appears in logs, renderer data, fixtures, or evidence.
